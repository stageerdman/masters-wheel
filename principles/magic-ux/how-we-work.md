# Magic UX: how we work

- Order: research (Columbo) → magic (Merlin) → UI spec (Jony) → clutter review (Eraser) → one final `SPEC.md` for the builder. The final spec wins where the files differ.
- One place per action. If a second path appears, cut one.
- Labels stay plain and literal. Magic lives in motion and tone, never in names that hide what's going on.
- Never show a "safe" or "done" signal before it's really true.
- Every problem state appears where the user looks (row, summary line) and has one fix in one place, with no dead ends.
- Count the steps for every main flow. A change that adds steps needs a reason: safety, consent, money or data loss.
